Redis에서 동시성을 다루는 도구 고르기

Oct 04, 20265 min read

  • 동시성
  • redis
  • valkey
  • lua

읽고, 판단하고, 쓰는 일이 어디서 얼마나 오래 걸리는지로 고른다.

상황쓰는 것
값을 올리거나, 없을 때만 넣는다명령 하나 (INCR, SET NX, HSETNX)
읽고 판단하고 쓰는데 판단이 단순하다Lua 스크립트 하나
읽은 뒤 판단을 프로그램이나 사람이 오래 걸려서 한다번호 비교. 쓸 때 “내가 읽었을 때의 번호와 같으면 쓴다”를 Lua 안에서 확인
여러 단계의 긴 작업을 한 번에 한 쪽만 해야 한다분산 락. SET NX에 만료 시간을 건다

위에서부터 본다. 위쪽으로 풀리면 아래쪽은 필요 없다.

명령 하나와 Lua가 막아 주는 것

Redis에서 명령 하나, Lua 스크립트 하나는 실행되는 동안 다른 명령이 끼어들지 못한다. 그래서 확인과 실행 사이의 틈에서 생기는 문제를 막는다.

  • 값을 쓰고 만료 시간을 거는 두 명령 사이에 프로그램이 죽어서, 만료 시간 없는 키가 영원히 남는 것.
  • “주인이 나인지 확인”과 “삭제” 사이에 다른 쪽이 주인을 바꿔서, 남의 것을 지우는 것.

할 일을 명령 하나나 스크립트 하나에 다 넣을 수 있으면 충돌 자체가 없다. 카운터를 올리는 데 번호를 비교하고 재시도하는 코드를 짤 필요가 없다.

막아 주지 못하는 것

원자적으로 실행된다는 건 도중에 끼어들지 못한다는 뜻이지, 낡은 정보를 들고 온 쪽을 걸러 준다는 뜻이 아니다. 스크립트를 부른 쪽이 이미 낡은 상태라면, 스크립트는 시킨 대로 정확하게 틀린 값을 쓴다.

이때의 틈은 스크립트 안에 있지 않다. 부른 쪽이 “내가 써도 된다”고 판단한 시점과 실제로 쓰는 시점 사이에 있다. 그 사이의 일은 스크립트에 넣을 수 없다.

그래서 번호 비교가 있다

쓰는 순간에 “그 사이 바뀌지 않았나”를 확인한다. 미리 잠그지 않고 쓸 때 충돌을 알아채는 방식이라 낙관적 락이라고 부른다.

  • 번호 비교가 낡은 쓰기를 알아챈다.
  • 원자성이 그 비교와 쓰기 사이에 아무도 못 끼어들게 해서 비교를 믿을 수 있게 만든다.

둘은 다른 일을 하고, 같이 써야 한다. 비교의 종류는 두 가지다. 값을 읽어 고쳐 쓰는 경우에는 “내가 읽었을 때의 번호와 같은가”를 보고, 권한을 가진 쪽을 가리는 경우에는 “내 번호가 더 새로운가”를 본다(낡은 쓰기를 번호로 막기).

WATCH로 키를 지켜보다가 바뀌었으면 쓰기를 취소하는 기능도 같은 목적이다. 다만 연결 하나를 그동안 붙잡고 있어야 한다.

분산 락은 마지막이다

충돌하면 다시 하면 되는 일이 아니라, 두 쪽이 동시에 시작하면 안 되는 일일 때 먼저 잠근다. 락에도 만료가 있으므로, 만료된 줄 모르고 쓰는 쪽을 막으려면 결국 번호 비교가 같이 필요하다.
